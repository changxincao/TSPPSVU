# SVU 人工数据 Experiment 1/2 runner：实现与验收（2026-09-14）

## 本轮范围与冻结口径

用户要求先完成前两个合成数值实验的模块化 runner，并明确“先跳过 moment”。本轮只实现 Experiment 1 的八个名义信息/权重方法以及 Experiment 2 的六个非矩稳健方法；没有改动 Moment-DRO、Olist、其他实验或原有求解模型。执行依据是 `TSPP_SVU_numerical_experiment_manual_cn_reconciled_20260914.tex` 的 Experiment 1/2 和最新 W1 半径文档：基线 Normal-Low，I=20、J=60、H=100、每个 final context 下1000个条件 OOS；20个独立 replication；30个验证 origin，各用最近70条历史预测下一条（t=71..100）；最终用100条历史。`h_i=min_{eligible j} r_ij`、选人上下限10%/70%、需求等式。相同 replication 的全部方法共用采购市场、历史、final context 和 OOS，不根据 OOS 选参。

## 模块与输入输出

- `TRBSVUProcurementGenerator`：用前轮完成的需求生成器 `typicalDemand()` 生成一份市场。覆盖率逐承运人取40%–70%并修补每条 lane 至少6家 eligible；费率、容量、MQC、现货倍率和 `h=min` 对照说明书。未改原市场参数。
- `TRBSVUSyntheticCase`：一份完整算例对象，含 `ProcurementParams`、lane 名、100条历史 `Sample`、final `CovariateVector`、1000条条件 OOS `Sample`、五个独立种子；`validationWindow(t,70)` 给出30个滑动验证窗口。方法调用只接受此对象，不会各自重抽样本。
- `TRBSVUSyntheticCaseIO`：以 v1 二进制格式保存/读回完整算例（采购参数、历史、当前 context、OOS 和种子），保存使用 `CREATE_NEW` 防止误覆盖。正式入口生成后立即保存并**读回这一份**供 Experiment 1/2 共用；旁边保存种子和配置文本。文件格式是项目内部快照，不是论文公开数据格式。
- `TRBSVUScenarioWeights`：D 的逐 lane 历史算术均值单场景、SAA-All 等权、Tuned-SAA 最近 `ceil(nγ)`、Exp/Gaussian/Epanechnikov/Triangular 四核权重。带宽 `B/n^(1/(l+4))`，l=4；指数和 Gaussian 用 log-sum-exp 型平移防数值下溢；compact kernels 零支持视为无效，绝不偷偷改成等权。所有权重方法复制 `Sample`，不污染共享算例。
- `analysis/trb_svu/rf_leaf_weights.py` + `TRBSVUForestWeights`：Python scikit-learn 多输出 `RandomForestRegressor`，正式固定500树、`max_features=1.0`、标准 bootstrap 和默认叶节点设置；每棵树对与 query 同叶的**原训练观测**均分 `1/T`，归一到非负且和为1。Java 适配器只让 Python 计算权重，随后仍用同一个 Java 采购求解器；同一个 case/origin 使用相同 RF seed 并缓存权重。小型测试为节时临时使用8树，不代表正式设置。运行环境本机验证 `scikit-learn 1.8.0` 可用；正式报告需固定 Python/package 版本。
- `TRBSVUSolveMethods`：名义权重使用现有 `SAAModel`；modified-χ² 使用现有 `DROModel` 的 DRO extensive 分支；RCSAA 强制现有精确变体，若误传 `DRO_EXTENSIVE` 直接拒绝；W1 使用现有 box-CCG 求解。所有 Config 显式 `enforceDemandEquality=true`。W1 每个训练窗口分别重算 `m_j=max_s d^s_j`，设置 `upper_j=1.5m_j`、`scale_j=Jm_j`，即模型距离 `sum_j |d_j-d'_j|/scale_j=(1/J)sum_j |d_j-d'_j|/m_j`；零 `m_j` 直接报错，不加任意 floor。U/C W1 只改概率、不改距离/box。χ²/RCSAA 删除真零权重场景，W1 允许真零权重。四参数 OOS recourse 入口改为 `public`，评价与求解同为需求等式。
- `TRBSVUExperiment1Runner`：D、SAA-All、Tuned-SAA（γ={.3,.6,.9,1}）、四核（B={.1,.5,1,3,5,10,30,50,100}）和 RF 共8种方法；独立调参并保留完整验证曲线；五个 contextual family 仅凭验证成本选 `C*`。若最终 compact-support query 对 B* 没有正权重，按预先固定规则升至下一个有正权重的网格 B 并同时记录验证 B 与最终有效 B；没有任何 OOS 选择。名义验证如未认证最优则报错。
- `TRBSVUExperiment2Runner`：直接继承同一算例及 Experiment 1 的 `C*`；RSAA、RCSAA、U-χ²、C-χ²、U-W1、C-W1 六种。前三类 λ 网格 {.01,.05,.1,.25,.5,1,2,5,10}，W1 绝对无量纲 ε 网格 {.005,.01,.025,.05,.1,.25,.5,1}，均在30个验证 origin 选最小真实采购成本，保留全部候选验证曲线；每个验证求解必须有最优证书，否则中止而非把时间限制下的 incumbent 误当参数比较。Moment-DRO 按用户指示未接入。
- `TRBSVUExperiment12Main`：每次处理一个 replication index，可选只跑实验1或顺序跑1+2；写完整 case、种子配置、方法主表和验证曲线 CSV。RCSAA 算法必须显式选 `repair`（LBBD_PRIMAL_SEARCH+repair cut）或 `compact`（LBBD_PRIMAL_EXACT+compact dual），不把未冻结的算法选择隐含在代码默认值。当前主表输出验证成本、选参、OOS Mean/样本 SD/线性插值 q95/max、spot 量占比、合同容量利用率、平均 MQC 罚金、目标、状态、gap、bound、最终求解时间、最优认证和选中承运人数；SD/q95 对齐旧 `BatchRunner` 的样本 SD 与线性插值分位数。

## 小型验收与证据边界

1. 新增/修改 Java 源以 CPLEX 22.1.1、Mosek 11 jar 编译通过。只修改 `BatchRunner` 的四参数 equality recourse 方法可见性；原三参数 `>=` 历史入口未改。
2. `TRBSVUSyntheticCaseSelfCheck`：20×60、100历史、1000 OOS、30个70条窗口、六DGP配对市场/context 的构造检查 PASS（前轮测试，本轮复用）。
3. `TRBSVURunnerSelfCheck`：7×4、100历史、5 OOS，完整算例二进制 roundtrip、四核和 RF 权重和、D/等式 OOS 接口 PASS。
4. `TRBSVURunnerSelfCheck robust`：同一小市场仅取3条训练场景，χ²、精确 RCSAA repair-search、W1 CCG 三个入口均返回有效解；该次 RCSAA `OPTIMAL` gap约3.17e-9，W1 `OPTIMAL_W1_CCG` gap 0，χ² `PrimalFeasible` gap 0。不能从此比较 OOS 优劣或推断正式实例速度。
5. `TRBSVURunnerSelfCheck experiment1`：仅1个验证 origin、8树、5 OOS的小型连通测试，八方法均返回；再次改动后复测通过。
6. `TRBSVURunnerSelfCheck experiment2`：同样小市场、1个验证 origin、λ仅{.1}、ε仅{.05}，六个非Moment方法均贯通。此处仅测试完整调度路径，不是正式训练内调参，也不是论文结果。

## 仍未完成/不能宣称的部分

### 术语澄清（用户追问）

`20×60` 是一个采购算例的规模：20家候选承运人（I=20）和60条运输 lane（J=60），不是20次重复乘60个数据集；20个独立 replication 是另一个维度。Experiment 2 的 U/C 不对应两套优化模型：对同一组历史需求点，U赋等概率，C赋Experiment 1训练内选出的条件概率；χ²或W1各只调用同一模型/求解入口。runner分成U/C行是为了独立验证选参和输出配对结果，模型实现共用`TRBSVUSolveMethods`。Moment本轮遵照用户“先跳过”未接；仓库旧RSOME Mean–MAD/PCM脚本是小型pilot及affine/lifted策略近似，和最新说明书提出的边际均值–方差+κ正式benchmark不同，不能直接改名接入。

- 尚未运行 I20×J60、20 replication、30-origin、1000 OOS 的正式实验；没有任何可用于论文方法排序的新统计结论。正式运行计算量极大，特别是精确 W1、RCSAA；当前入口每个 replication 单独输出，**没有中途候选级 checkpoint/自动断点恢复**，启动全量前应先做定时 pilot 和持久化规划。
- W1-CCG 当前 `timeLimitSeconds` 被底层 master/oracle 用作各次求解的时间限制，不能误解为整个外层 CCG 的严格总墙钟上限；正式批量实验必须另加全局 watchdog/可恢复检查点后才适合无人值守运行。
- `TRBSVUExperiment12Main` 当前只执行 Normal-Low baseline；其余DGP、规模、Olist属于后续实验，不应误称已实现。Moment 按用户明确要求跳过。
- RF 软件与 secondary hyperparameters 现取 scikit-learn standard defaults；若论文最终另定叶节点数等，需同步代码和记录。主表的当前时间仅 final solve，不含验证、RF 拟合、OOS LP；若需要端到端时间须另设字段。
- χ² 现有 `DROModel` 对非常小的正权重会做 1e-8 floor 并重归一；真正零权重在适配层已删除。这个数值政策应在正式 pilot 中检查对选中 C* 的影响；不能把 floor 后求得的目标说成原始极小权重分布的完全精确结果。
- 输入算例二进制已可保存/恢复；本轮仅小规模 roundtrip 检查，正式大算例仍需对文件 hash、版本和读回一致性验收。
