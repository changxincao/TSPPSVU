# 远程实验快速操作规范：只压缩执行冗余

日期：2026-10-01

## 1. 范围

本文只讨论助手在执行已经明确的任务时如何减少冗余操作、缩短响应时间。数据口径、模型版本、参数范围和实验方案发生变化属于研究过程本身，不视为可消除的操作浪费。

## 2. 此前真正存在的操作冗余

### 2.1 同一状态被反复查询

此前经常把一次状态判断拆成多次SSH：先查控制器，再查Java进程，再查日志，再查结果数量。每次都重新建立连接，产生明显等待。

改进：一次远程命令同时返回：控制器状态、queued/running/completed/failed、worker PID与CPU增量、最近事件、关键输出数量和stderr异常。正常时不读取完整日志，不递归扫描全部目录。

### 2.2 可以并行的主机操作被串行执行

新旧两台电脑互不依赖，但此前常先完整处理一台，再处理另一台；本地语法检查、远程连通性检查和已有结果清点也经常串行。

改进：以下工作默认并行发出：

- 两台远程机器的只读状态查询；
- 本地脚本检查与远程环境检查；
- 不同主机上的部署和启动；
- 远程求解与本地结果整理/文档记录。

只有同一输出目录或存在明确前后依赖的步骤才串行。

### 2.3 部署被拆成多轮

此前出现逐文件上传、逐文件核对、发现遗漏后再上传的情况。

改进：先形成本轮变更文件清单，一次完成全部脚本语法检查、本地哈希、批量上传、远程哈希返回和自动比较。未改变的文件不上传、不重新核对。

### 2.4 每次都做全量审计

此前有时只是改了调度参数，却重新检查输入、class版本、数学模型、历史结果和全部脚本。

改进：只检查本次操作影响到的层级：

| 本次变化 | 只需检查 |
|---|---|
| 并行数、队列顺序 | 控制器脚本、任务数、并行上限、恢复逻辑 |
| seed或新增replication | 新输入数量、seed、配对hash |
| 参数网格 | 候选列表、选择结果、checkpoint协议 |
| Java源码 | 编译、class major、相关回归测试、class hash |
| 统计脚本 | 原始数据读取、配对和公式，不重跑求解 |
| 仅查询进度 | 状态、进程和最近事件，不做代码/输入审计 |

### 2.5 启动前做了非关键整理

README、历史目录归档、无用文件整理、完整统计和长篇记录有时被放在启动关键路径上，导致已可运行的任务没有及时启动。

改进：关键路径只保留：

`修改 -> 最小检查 -> 部署 -> 启动 -> 一次启动验收`

README、长期记录、归档、清理、表格和图形在任务启动后并行完成。

### 2.6 为一次操作创建过多一次性脚本

此前增补query、带宽刷新、失败补跑、不同CV档和DRO追加分别创建脚本，后续需要反复寻找哪个入口仍有效。

改进：优先扩展已有参数化runner。通用runner暴露experiment root、cell列表、replication范围、方法列表、参数网格、最大并行数、solver线程数和skip-completed/resume。一次性wrapper只负责传参，不复制调度逻辑。

### 2.7 状态监测频率过高且没有事件门槛

运行正常时高频轮询只会重复得到相同结果。

改进：启动后立即验收一次；之后由定时监测读取聚合状态。无实质变化保持安静；仅在任务完成、失败、重试耗尽、状态长期不更新或用户主动询问时深入检查。用户询问时直接给最新快照，不顺带执行无关审计。

### 2.8 SSH失败后的处理过度展开

此前一次连接超时后，有时连续尝试多种远程命令、代理和诊断，拖慢主要任务。

改进：普通SSH重试一次；再检查Tailscale在线状态及VPN路由；仍不可达则报告该主机暂不可用，不阻塞另一台主机。只有用户要求修复连接时才进一步诊断。

### 2.9 结果完整性检查被反复手工执行

此前多次分别统计complete标记、summary数量、query目录和失败日志。

改进：每种实验使用一个统一验收命令，一次产生预期任务数、完成/失败/缺失、query数量、必要solve/OOS文件、hash配对、未认证解和可进入统计的结果清单。同一批次没有文件变化时复用上一次验收快照。

## 3. 后续默认的快速执行顺序

### 第一步：形成执行卡

只写执行所需信息：`主机、根目录、入口、rep范围、方法、并行数、线程数、是否跳过已完成项`。研究口径已经由用户给定时，不再重新论证。

### 第二步：并行预检

同时执行本地改动脚本检查、远程连通性和目标目录检查；如涉及另一台机器，同时查询其状态。

### 第三步：一次部署和启动

批量上传变更文件、一次哈希核对、立即启动。文档整理和全面统计不挡在启动前。

### 第四步：一次启动验收

在一条远程命令中确认控制器、worker数、CPU增长、状态更新时间和failed计数。通过后结束人工操作。

### 第五步：事件驱动监测

不进行无意义的连续人工轮询。异常时只读取对应任务的日志，不扫描正常任务。

## 4. 可以并行的具体清单

| 操作 | 是否可并行 | 条件 |
|---|---:|---|
| 本地脚本语法检查与远程连通性检查 | 是 | 无共享写入 |
| 两台远程机器的独立任务 | 是 | 各自独立输出根目录 |
| 多个变更文件的哈希计算 | 是 | 一次汇总结果 |
| 远程求解与本地文档/统计工作 | 是 | 不修改正在使用的代码和输出 |
| 同一机器上的不同方法/replication | 是 | 统一受全局并行上限控制 |
| 基础方法与已满足依赖的DRO | 是 | DRO所需中心分布已经确定 |
| 输入生成与依赖这些输入的求解 | 否 | 必须先完成并核验输入 |
| 同一输出文件的两个worker | 否 | 会发生覆盖竞争 |
| 代码热更新与使用旧class的任务 | 原则上否 | 除非部署目录版本隔离 |

## 5. 每次操作最多保留的检查次数

- 语法检查：改完后1次；再次修改才重查。
- 本地/远程哈希：部署后1次。
- 输入审计：输入生成后1次。
- 启动验收：启动后1次。
- 正常进度查询：按用户询问或阶段事件，不重复全审计。
- 完成验收：阶段结束后1次。

## 6. 助手后续执行约束

1. 先做能直接推进任务的操作，说明文档和归档移出关键路径。
2. 能用一条命令返回的信息，不拆成多次工具调用。
3. 能同时检查的独立主机或本地任务，使用并行调用。
4. 没有异常证据时，不重复证明同一件事。
5. 用户只问状态时，只做只读状态查询，不顺带改代码或重新部署。
6. 用户要求启动时，完成最小必要检查后立即启动，不追加无关研究分析。
7. 若发现理解可能造成不同目录、不同任务数或覆盖旧结果，只确认该关键歧义；其余细节按既定规范处理。

## 7. 本次操作本可如何压缩

本次统一20组任务，本可压缩为：

1. 一次确认统一根目录和20组范围；
2. 本地同时完成脚本修改与输入映射检查；
3. 一次上传4个变更脚本；
4. 一次远程命令完成哈希核对并启动；
5. 一次启动验收。

不需要在关键路径中检查旧电脑、反复读取旧状态文件、逐文件部署，也不需要先写完整操作记录。以后同类任务按这一五步模板执行。

## 8. MotionPro与Tailscale路由冲突及恢复

2026-10-01确认：MotionPro连接后，为新电脑 `100.71.236.93/32` 注入了一条经物理网卡和网关 `111.187.64.1` 的精确路由。其总Metric为25；Tailscale同一 `/32` 路由原总Metric为26，因此Windows错误地优先选择MotionPro路径，普通SSH超时。`tailscale ping`仍能成功，因为它不依赖该系统路由选择。

本次使用管理员PowerShell，将新电脑对应的Tailscale活动路由Metric从21调整为1：

```powershell
$route = Get-NetRoute -AddressFamily IPv4 `
  -DestinationPrefix '100.71.236.93/32' `
  -InterfaceAlias 'Tailscale'
Set-NetRoute -InputObject $route -RouteMetric 1
```

调整后：

- Tailscale总Metric：`1 + 5 = 6`；
- MotionPro路径总Metric：`0 + 25 = 25`；
- MotionPro保持连接时，SSH到 `100.71.236.93` 实测成功。

该设置属于活动路由，Tailscale重启、电脑重启或网络重置后可能恢复。若再次出现“`tailscale ping`成功但SSH超时”，先执行：

```powershell
Get-NetRoute -AddressFamily IPv4 -DestinationPrefix '100.71.236.93/32' |
  Select-Object DestinationPrefix,NextHop,InterfaceAlias,RouteMetric,InterfaceMetric
```

若Tailscale路由再次落后，以上述管理员命令重新设为1。若需恢复原值：

```powershell
$route = Get-NetRoute -AddressFamily IPv4 `
  -DestinationPrefix '100.71.236.93/32' `
  -InterfaceAlias 'Tailscale'
Set-NetRoute -InputObject $route -RouteMetric 21
```

目前只修改新电脑的精确路由，没有修改整个 `100.64.0.0/10`，也没有修改MotionPro配置或其他VPN流量。
